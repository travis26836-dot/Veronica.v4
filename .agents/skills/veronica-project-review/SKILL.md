description: Review Veronica project progress, choose a bounded development packet, or run its daily hygiene and weekly milestone review using repository evidence.
---

Read docs/PROJECT-WORKFLOW.md, docs/GOALS.md, docs/CURRENT-STATE.md and its named
decision, TODO.md and the repository collaboration contract before project work.
Product completion remains SOURCE-OF-TRUTH.md section 11.

For a review, inspect current Git status and relevant evidence. Check remote state
through an available authenticated tool or read-only git query; distinguish
cached origin refs from live GitHub. Missing access means unknown, not unchanged.
Compare worktrees/branches read-only when a named earlier implementation is absent.

Classify dirty groups as keep/review/commit/discard candidate with rationale.
Preserve raw private runs; publishable evidence needs review. Report at most three
important changes and one next packet. Stay quiet on unchanged scheduled reviews.
Honor daily/weekly due times; repeated early heartbeat wakes are not new reviews.

For development, select a ready goal and use docs/GOAL-TEMPLATE.md. Claim its
paths, implement, validate, record evidence and hand off. Preserve full command
results and poll yielded session IDs before restarting tests. Never claim a hang
from partial output alone. Completion, local commit, push and qualification are
different facts. App task goals do not automatically propagate project-wide.

Route scores through evaluator/runtime/prompt/foundation diagnosis before any
training proposal. The review skill itself grants no paid-run or training consent.
Use the existing evaluation and startup workflows for those specialized tasks.
